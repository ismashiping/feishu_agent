# 从兼容迁移到单一路径

## 是什么

兼容层让旧导入路径临时指向新实现，适合渐进迁移。Phase 1–4 用它保护未提交工作和历史调用方；Phase 5 在仓库内调用方全部迁走后，删除这些临时入口，只保留 canonical 路径。

## 为什么不能直接删除

Python 文件只有几行不代表无调用方。测试会 monkeypatch 模块全局，Docker 可能执行旧 `python -m`，console script 可能仍由旧安装元数据生成，可运行教材也可能是实际验收入口。直接删除会把结构整理变成运行时故障。

## 底层原理

安全删除需要同时证明：

1. 静态引用归零：活动源码、测试、脚本和部署配置不再导入旧路径。
2. 动态入口迁移：console、`python -m`、框架注册和 importlib 字符串使用新路径。
3. 行为契约不变：Graph、OpenAPI、DDL、飞书状态与资源关闭继续由原测试验证。
4. 发布物收口：wheel 不再包含旧文件，避免源码仓库干净但安装包仍暴露旧模块。

旧模块删除后，`ModuleNotFoundError` 是有意的新契约。正式 CLI、HTTP 和飞书消息协议仍保持兼容；只有未声明的旧 Python 内部导入被收口。

## 最小 Demo

`demo.py` 导入 Agents、API、RAG、DB 和飞书的 representative canonical 模块，并验证四类旧路径无法导入。它证明当前安装视图，不代替完整回归或真实外部系统测试。

## 工程取舍

历史 Markdown、before 快照和验收日志保留旧路径原文，因为它们记录当时事实。活动 Python 和部署入口必须迁移。已提前退役且没有 canonical 对应的 PMC 模块不混入本轮，避免用“清理兼容层”掩盖业务能力删除。
