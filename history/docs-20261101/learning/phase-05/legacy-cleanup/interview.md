# 面试题与口述答案

## 为什么兼容层不能长期保留？

它降低迁移风险，但长期存在会扩大公开导入面、让 patch 和动态导入出现两套路径，并增加发布物与文档维护成本。应在调用方迁完、行为验证完成后有计划地删除。

## 如何证明一个旧模块可以删除？

我会同时检查静态导入、动态 import 字符串、框架注册、console entry point、Docker/Compose、测试 patch 目标和 wheel 内容；再运行 canonical 行为测试。只有“没有引用”和“新路径行为保持”同时满足才删除。

## 为什么保留历史文档中的旧路径？

验收记录和 before 快照描述的是当时事实，改写会破坏审计证据。活动教程和脚本要迁移，历史原件则通过目录 allowlist 排除，不伪装成当前入口。

## 删除失败如何回滚？

按批次恢复小型别名文件和该批入口配置，不回滚 canonical 实现，也不使用整个工作区 reset 覆盖其他未提交修改。这样回滚范围和风险可控。

## 30 秒口述

我在四个迁移阶段先建立 canonical 模块并保留同对象兼容层，第五阶段才清理旧路径。删除前冻结映射、活动引用、影响和回滚方案，并获得明确授权；随后按 Agents、API、RAG/DB、飞书分批迁移调用方和验证。API 聚合 wrapper 按 Schema、执行、runtime 三个真实职责拆回正确导入；飞书同时更新 console、Docker、Compose 和 wheel 包发现。最后用旧导入失败、canonical 隔离导入、Graph/OpenAPI/DDL/飞书契约、完整回归和 wheel 内容共同证明收口。
