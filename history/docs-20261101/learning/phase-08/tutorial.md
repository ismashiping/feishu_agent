# 版本发布与原子性

原存储以PDF内容hash或PMID去重，同PMID摘要变化只返回needs_update。版本发布补上明确的显式更新操作：保持document_id，归档旧PreparedIngestion，再原子切换当前documents/chunks。旧报告保留的chunk ID/hash/原文不改变含义，新活跃片段使用版本UUID重新命名。

版本签名包含文档内容/元数据、来源单元、解析和分块身份，不包含抓取路径、时间和向量数值。重复同输入不新增版本；元数据改变也保留版本。模型/分块策略改变拒绝，需要未来显式重建，不混用向量空间。

数据库事务锁定一份文档，旧快照归档和新活跃切换一起提交。插入失败全部回滚，旧证据继续可见。JSONB归档包含原向量，属于内部读取，不进入公开回答。历史物理文件仍需保留，版本表不替代原PDF/XML文件备份。

## P8-03：身份关联与状态不是原文版本

别名是人工登记的标识关联；同一标识可能出现多个文档，必须展示冲突。它不重写文档UUID或chunk，也不自动判两篇论文为同一研究。状态是对来源的新断言，单独保存事件和当前投影，因此撤稿后仍能回看旧证据。用expected_event_id比较并交换可以防止两名操作者互相覆盖；事件和投影同事务避免半成功。无记录默认为unreviewed，不能把缺少撤稿通知解释为已验证正常。详细运行与流程图见[source-governance.md](source-governance.md)。

## 在线窗口与重建

增量游标的意义是“之前范围已安全处理”，所以被截断的PubMed结果不能推进为完整窗口。先冻结一次完整发现，再处理文档，恢复不会因为在线排序变化漏掉条目。重建则用候选payload隔离耗时计算，最后以全库来源签名作比较交换：源变了就拒绝切换。PostgreSQL表锁只覆盖最后短事务，旧查询的快照与历史证据保持。工程自检与医学评价分开记录，详见[maintenance.md](maintenance.md)。
