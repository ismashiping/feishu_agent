# P0-08 SPEC：学习文档与 Phase 0 独立验收

版本：0.1；日期：2026-10-26；范围：P0-08。最终结果见 [阶段验收报告](../../phase0-acceptance.md)。

## 1. 背景及目标

P0-01–07 已有调研、设计、真实 TDD、Windows 环境及 wheel 验证。本任务将它们转为初学者可学习、可复现的材料，并按独立清单验收 Phase 0。独立指验收清单和执行记录独立于教程撰写，由本次执行者核验；不代表第三方审计。

## 2. 功能需求

创建 docs/learning/phase-00/ 下 README、tutorial、code-walkthrough、exercises、interview、troubleshooting 六份 Markdown。按“是什么 → 为什么 → 原理 → Demo → 真实代码 → 流程 → 调试测试 → 修改练习 → 独立实现 → 面试表达”组织。解释实际模块、函数、输入输出、生命周期、异常与设计取舍；提供可运行示例和实际执行流程图。

## 3. 非功能需求

面向刚接触 Python 工程的读者，先解释术语再解释代码；程序名、路径和行为以当前源码为准。每个标记为 Python 的围栏都是完整可执行示例，使用固定假值，不读取真实密钥。示例在最小环境、临时 cwd、项目解释器及 10 秒超时下运行。文档内引用可追溯到源文件/SPEC/记录，不编造验证结果。

## 4. 本阶段不实现的内容

无新业务、依赖或正式测试功能，不实现 Phase 1。练习为读者作业，不修改当前产品契约。没有功能变更时不制造 RED；若复验发现代码缺陷，先补真实失败测试再修复，单列过程。Linux、无缓存下载和真实服务不是本次 Windows Phase 0 骨架验收通过的含义。

## 5. 输入输出契约

输入：六个源模块、五个测试文件、现有 SPEC/架构/技术选型、P0-07 历史日志及 wheel。输出：六份学习文档、docs/phase0-acceptance.md、进度/导航/状态更新；本地 .artifacts/p0-08-日期-序号/ 保存复验输出。只新增本次目录，不覆盖先前证据。

## 6. 数据模型

不添加 Python 模型。报告按验收项 ID、要求、实际证据、结论、范围/局限组织；历史 TDD 与本次复验分别标记。P0-T01–07 沿用总体 SPEC；P0-A01–06 是本任务文档/演示验收项，不混算为新增 pytest 用例。

## 7. 核心流程

读 SPEC/源码/测试 → 冻结本清单 → 编写学习材料 → 从围栏抽取示例执行 → 新输出目录执行回归/质量检查/双入口 Demo → 核对历史锁/环境/wheel/TDD 证据 → 审阅术语/流程/链接/练习 → 写入报告和阶段进度 → 停止。Phase 0 完成后仍需用户指定 P1-01 才进入业务开发。

## 8. 异常与边界场景

不存在的学习目录是待交付事实，不计功能 RED。示例缺模块、错误入口、参数不符、隐式依赖主机环境、输出混流或超时均不能算示例通过；先修正文档，若属于产品缺陷按 TDD 修复。覆盖率不含未采集子进程须注明；缓存安装、wheel 标签、Mock 生命周期不推导真实外部能力。

## 10. 可执行验收标准

项目 .venv/Scripts/python.exe 执行：`-I -m pytest tests/unit tests/integration --cov=clinical_agent --cov-branch --cov-report=term-missing`，保留输出；执行 `-m ruff check src tests`、`-m ruff format --check src tests`、`-m mypy src`、`-m uv lock --check --offline`、`-m uv pip check --python <项目解释器>`。清理并恢复 pytest 注入变量，覆盖率/临时输出指定本次目录。

另用本地临时验证脚本抽取全部 Python 围栏，按第 3 节执行；校验学习清单、Markdown 围栏/本地链接/锚点、函数/模块来源、受保护文件哈希及 wheel SHA256。重新执行教程 PowerShell Demo 的语义场景，不运行练习中的未来改动。静态核查、Demo、pytest 的数目分别报告。
