# SPEC 08：增量更新、去重与幂等

版本：0.1；状态：未来阶段概要，开发前细化；未实现。

## 1. 背景及目标

扩展 Phase 1 已具备的基础幂等，使已有来源变化、定期同步和重复执行有明确版本行为；保留历史报告的证据定位。不能把“此前完全没有去重”当本阶段起点。

## 2. 功能需求

- P8-F01：按来源身份、规范化外部标识与内容哈希区分未变、内容更新和仅元数据更新，歧义不自动归并。
- P8-F02：文档内容更新生成新版本及片段，成功后原子切换活跃版本；历史版本仍能被报告引用。
- P8-F03：记录增量游标、查询窗口和执行结果；只在对应批次持久化成功后推进，重叠时间窗口靠幂等吸收重复。
- P8-F04：提供一次性更新命令及简单可配置调度入口，不默认引入复杂调度平台。
- P8-F05：变更后可触发固定小型回归评估并记录结果；完整评估引擎在 Phase 9，不因阶段依赖造成循环。

## 3. 非功能需求

单文档版本发布为原子操作，embedding 在写事务外完成；旧版本在新版本失败时仍可检索。唯一约束/必要行锁处理并发，不做分布式事务。模型/分块版本变化不得混合向量空间，需要显式重建流程与回归结果。

## 4. 本阶段不实现的内容

不实现全网抓取、删除历史证据、无限自动重试、自动消解所有 DOI/PMID 冲突或复杂事件溯源平台。定期任务的实际频率和授权在任务实施时配置，本 SPEC 不创建本机或聊天自动化。

## 5. 输入输出契约

UpdateRequest(source_scope, query/date_window 或本地集合, resume_cursor 可空, dry_run)。UpdateResult(run_id, unchanged/created/updated/metadata_updated/failed/conflicted 计数, item_results, cursor_before/after, evaluation_status)。

dry_run 输出计划差异，不改文档/游标，不下载并发布新模型向量。重试已提交批次可返回 unchanged，不能重复增加有效版本。部分失败是否阻止游标推进必须在细任务冻结，默认不得越过未成功范围丢数据。

## 6. 数据模型

Document 保持稳定内部身份；DocumentVersion 记录 version_id、content_hash、metadata_hash、source_snapshot、model/chunking 身份、时间及状态；EvidenceChunk 关联不可变版本。SourceAlias 保存跨来源同一身份的映射与依据，冲突标记待处理。

UpdateRun/Cursor 是简单运行记录，记录范围、成功/失败项和游标。内容不变但元数据变化也保留审计，不覆盖历史报告所用快照。撤回/更正作为来源状态更新，不能直接删掉关联历史证据。

## 7. 核心业务流程

确定范围及上次游标 → 拉取有限候选 → 校验身份/内容差异 → dry_run 或解析/分块/编码 → 原子发布新版本 → 记录逐项结果 → 安全推进游标 → 触发小型回归 → 呈现运行结果。模型变化时构建独立检索空间，验证后切换，不边更新边混查。

## 8. 异常与边界场景

同 PMID 内容变化、同 DOI 多个记录、同名 PDF 不同内容、同内容不同路径、元数据更正、撤回、旧页码改变、网络中断、游标落盘失败、并发同项更新、重建失败、调度重入。无变更也应有明确结果，不制造新版本充数。

## 9. 测试用例清单

- P8-T01：首次、相同输入再执行、内容变更、仅元数据变化和 dry_run。
- P8-T02：真实数据库约束、并发发布、新版本失败时旧版保持可用。
- P8-T03：历史报告精确回指旧片段/页码，活跃检索只用正确版本。
- P8-T04：中断、部分失败、游标重放与重叠时间窗口不丢数据。
- P8-T05：跨来源冲突、别名、撤回/更正与模型维度变化。
- P8-T06：调度重入限制及固定回归评估触发成功/失败/未执行状态。

## 10. 可执行验收标准

实施时运行 `uv run pytest tests/unit tests/integration -k knowledge_update`。真实数据库对同一更新重复/并发执行后，活跃版本与片段数符合预期；任意发布失败不影响旧版；历史引用仍可重现。

在测试批次中注入中断并从原游标重跑，所有成功项不重复、失败项不丢失；dry_run 前后数据库与游标一致。评估未运行或失败时结果明确，不伪标更新质量通过。当前未执行更新命令或调度。

## 11. 阶段依赖及完成定义（DoD）

依赖 Phase 7 已验收。细化来源匹配、版本保留、游标和调度配置后 TDD；完成真实数据库/中断恢复/历史报告回归及 docs/learning/phase-08/ 才完成。Phase 9 在此前固定回归样例基础上建立完整评价体系。
