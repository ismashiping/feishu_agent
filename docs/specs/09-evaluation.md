# SPEC 09：离线评价、引用准确性与性能回归

## 当前状态（2026-10-28）

用户授权开展 Phase 9。离线核心已按[实施契约](tasks/p9-evaluation.md)开发，包含冻结合成公式集、指标/失败/拒答、基线门禁和一次性报告、评价器微基准；历史真实观察集保持独立复算。详细实测见[阶段报告](../phase9-acceptance.md)。

完整阶段仍受医学人工标签、真实固定模型评估及服务满载/进程内存实验缺口限制，不能以离线核心替代本规格完整DoD。原有各阶段未签署事项保持待审。下文保留完整需求作为尚需验收的依据。

## 1. 背景及目标

用固定、可追溯的数据和明确指标比较检索、回答、引用及性能，发现回归；本阶段扩展已有测试，不是到此才开始测试。医学正确性不能只靠另一个 LLM 自动打分。

## 2. 功能需求

- P9-F01：建立版本化离线数据集，记录问题、相关片段/文献、允许结论、不可支持断言、引用和人工标注依据。
- P9-F02：评估检索 Recall@k/MRR 或 nDCG、引用身份准确性、定位正确性、结论支持度及引用覆盖率。
- P9-F03：区分模型生成失败、依赖故障、无证据正确拒答和错误拒答；不能把失败样本排除后报高分。
- P9-F04：记录受控环境吞吐、p50/p95 延迟、峰值内存和并发饱和行为，比较固定基线。
- P9-F05：提供一次性自动运行及机器可读/可读报告，对已冻结门槛给 pass/fail/inconclusive。CI 只运行小型确定性离线集，昂贵真实模型测试单列。

## 3. 非功能需求

保存 dataset、标注、代码/依赖锁、模型 revision、检索配置、prompt、硬件和执行范围；随机性参数和不可重复因素明确记录。数据与调参集分离，不依据测试结果临时改标签。语料使用人工/有合法使用依据的样例，避免把个人敏感数据写入公开测试产物。

## 4. 本阶段不实现的内容

不宣称自动评价代表临床有效性、不以 LLM-as-judge 单独决定验收、不建立训练平台或大型线上实验系统。性能预算未冻结前不声称达到生产容量；不把公网变动当确定性单元测试。

## 5. 输入输出契约

EvaluationRequest(dataset_version, configuration, run_scope=offline/model/external/performance, baseline_run_id 可空)。EvaluationRun 包含 run_id、provenance、逐样本结果、指标值/分母、错误及未执行计数、预算、比较结果和 overall_status。

每个样本保留检索/答案/引用输出与失败原因，实际耗时及使用服务范围。无可评估样本或分母为零返回 not_applicable/inconclusive，不把 0/0 当作 100%。外部验证未运行不能默认为通过。

## 6. 数据模型

EvaluationCase 包含 case_id、question、evidence_scope、relevant_chunk_ids、expected_claims、forbidden_claims、source_snapshots、annotation_version。复杂问题应拆可标注的原子结论；人工评审有 disagreement/unknown 状态。

MetricResult 保存 name、value 可空、numerator/denominator、unit、aggregation、scope 和 threshold。引用身份准确性与结论支持度分开：真实 PMID 但不支持结论不能得“引用完全正确”；未给引用的实质结论计入覆盖率缺失。

## 7. 核心业务流程

冻结数据与门槛 → 运行固定配置/模式 → 收集全部成功/失败样本 → 确定性来源/定位检查 → 检索指标及人工标注支持度评价 → 可选模型评审作为辅助 → 固定硬件/并发性能实验 → 与基线对比 → 产出带限制的报告。不自动用不完整运行覆盖有效基线。

## 8. 异常与边界场景

缺标注、重复 case_id、无相关文献问题、正确拒答、模型超时、引用存在但结论无支持、错误标注、数据集泄漏、不同硬件比较、缓存冷热差异、小样本和部分执行。性能实验必须统计超时/拒绝，不只测已完成快请求。

## 9. 测试用例清单

- P9-T01：手算小集指标、空分母、缺标注和重复样本。
- P9-T02：伪造 PMID/未知片段、真实但无支持引用、无引用结论及正确拒答。
- P9-T03：失败样本计数、未执行外部验证、分组汇总和门槛判断。
- P9-T04：同配置 Fake 下报告确定性，基线及 provenance 完整。
- P9-T05：真实固定模型离线集评估与人工抽查，另列成本及随机性。
- P9-T06：并发递增、满载、外部超时、资源释放和旧功能全量回归。

## 10. 可执行验收标准

实施时运行 `uv run pytest tests/unit tests/integration -k evaluation` 并执行全量离线回归。先用手算 fixtures 验证公式、分母和分组，再运行真实评估入口；实际入口名称由本阶段任务 SPEC 固定，当前不虚构已存在命令。

确定性门禁：注入的未知来源/标识必须全部检出，错误 metadata 不得被自动改成合法引用；每个实质性结论有证据关联或明确被判不支持。真实检索/支持度指标、回归容忍度和性能预算须在首个实验前冻结为机器可读配置，记录数据集规模及硬件；不达门槛如实 fail，验证不足为 inconclusive。

## 11. 阶段依赖及完成定义（DoD）

依赖 Phase 8 验收及此前各阶段真实测试证据。细化指标公式、标注流程、预算和报告命令后编写测试与最小实现，阶段末集中验收；完整评估产物、人工复核、离线/外部/性能结果分开、回归门禁及 docs/learning/phase-09/ 齐备后验收。项目总体完成还需核对 G-01–12，未验证外部功能不得靠总分掩盖。
