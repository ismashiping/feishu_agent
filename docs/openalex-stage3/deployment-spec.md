顺序：核对容器/实际库/head → 构建锁定依赖镜像（运行服务暂不变）→ 暂停API/机器人 → pg_dump业务库并校验备份 → 用新镜像显式升级Alembic → 重建API/机器人 → readiness/依赖/版本/机器人连接检查 → HTTP真实五题规划、OpenAlex检索、筛选、全文、生成、引用检查 → 原因分类及结果归档。

验收断言：实际业务库head=oa3001_0009；旧表数据保留；OA表存在；两个应用容器使用新镜像、API ready、机器人连接成功；五题分别保存原始HTTP结果/耗时/来源/时间/全文证据和失败原因。至少尝试实际发现到全文回答，不以缓存回放替代。空候选、摘要回退、超时、引用拒绝均按真实结果记失败或partial，不能只检查HTTP200。关键结论定位到保存的原始证据；题意/医学支持由工程AI复核列出，不冒签专家结论。
