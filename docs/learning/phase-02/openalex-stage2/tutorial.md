# 从零理解科研检索

## 是什么
OpenAlex提供文献元数据。API响应中的倒排索引是“单词到位置列表”，把位置倒过来排序才能恢复摘要。摘要不是全文，OA链接也不是许可证明。

## 为什么需要
中文问题中的对象、任务、影像模态、终点和时间会限制哪些研究可回答问题。词面同时出现不代表同一任务。系统先在文档层筛选，再让后续阶段从已选文献寻找全文证据。

## 原理与最小Demo
先运行demo.py。resolve_dates用日历月份计算窗口，不用365天乘年数；2026-10-29的最新24个月起点是2024-10-29。decode_abstract不猜缺失位置，坏索引保留失败状态。

## 真实项目
PicoPlanner复用一个LLM调用输出PICO和research_constraints；只对新契约中的唯一逐字原文引用用代码确定偏移，歧义不猜。OpenAlexRetrievalService编译英文查询、调用HTTP适配器，再批量请求screen_candidates。模型每项判断必须返回实际候选ID和原句，违约项排除并标partial。

## 设计取舍
不用新的检索框架和Agent。复用HTTPX、Pydantic、LangChain、已有DTO与资源上下文。请求局部候选不自动写documents表，所以本阶段不改库；缓存身份迁移归全文阶段。限定轮数、候选和字节数，不能据字节预算宣称精确Token费用。

## 局限
真实搜索可能限流或缺摘要，单次模型规划不保证稳定。来源ID与引文校验只证明关联，医学支持关系需独立复核。
