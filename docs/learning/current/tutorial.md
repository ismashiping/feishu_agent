# 是什么、为什么、如何执行

## 是什么

RAG 将找到的文本放入生成模型上下文，让回答可依据文献，而非只依赖模型记忆。Embedding 将文本变成向量，用于相似度计算；它不验证医学结论。pgvector 为 PostgreSQL 增加向量存储和运算能力。

## 为什么需要这些组件

OpenAlex 发现论文，全文下载取得证据，切分控制模型输入长度，向量检索挑出相关片段，Pydantic 限制结构，来源核验确保引用与已取得材料一致。LangGraph 组织这些步骤及有界反馈。每个组件解决不同问题，不能把“已入库”理解为“所有查询都自动搜索它”。

## 底层原理

当前缓存键是论文身份，签名还包含解析/Embedding 信息。enrich_openalex 对本次在线结果逐篇查缓存；未命中才下载，SentenceSplitter 切分，E5 编码，持久化文本与向量。已有缓存可避免重复下载及编码，但在线论文发现仍先发生。

相似度与词项/章节规则决定选入哪些段落，最终事实、推断和待验证假设仍需分清。引用定位检查保证引文来自对应片段，不能自动证明临床正确性。

## 最小 Demo

先运行 demo.py。QuestionBody 在资源装配前拒绝 local。ValidationError 是输入契约错误；应映射输入错误，而不是 502 上游错误。

完整调用图见 ../../current/architecture.md。学习顺序从 HTTP/CLI 输入开始，沿 ResearchService 读到 Scout、全文、生成和引用检查；不要从所有数据库表开始背诵。
