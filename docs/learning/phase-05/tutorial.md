# 两路召回为什么需要排名融合

关键词检索寻找文字匹配，向量检索寻找编码空间相似性。例如aspirin与analgesic可能在合成向量例子中相近，但aspirin的字面命中可能更有用。两种分数的数值含义不同，不能直接相加。

RRF只使用排名。每一路第r位贡献1/(60+r)，两路同一chunk累加，缺通道不加分。例子中同一chunk排1和2，分数为1/61+1/62。同分按chunk UUID升序，结果可重复。分数不是疗效概率或证据质量等级。

本阶段使用PostgreSQL simple配置生成tsvector，并用plainto_tsquery把查询转为词项与关系，不执行用户给的SQL或原始tsquery语法。ts_rank_cd用归一化32，便于展示有界分数；这不是BM25。GIN是该词项集合的数据库索引，不是第二份文献。

语言范围要诚实：默认simple不提供本项目已验证的中文分词。keyword/hybrid要求ASCII检索文本；中文原问题可配英文keyword_query，向量仍读取中文原问题。纯vector行为不变，未支持语言明确报错，不偷偷变成另一模式。

日期过滤仅接纳已知完整出版日，未知/仅年/月精度不补造某日。来源、内容范围、文档ID和日期在两通道查询限额前应用。候选集有上限，融合后仍可能漏掉候选之外的相关证据。
