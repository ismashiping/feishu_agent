# 原理：先组织证据，再写回答

科研综述是围绕问题整合多项研究。摘要列表只能逐项说明“谁做了什么”；综述还要说明不同技术方向的联系、条件和限制。多找论文不能自动得到综述，先筛出正确任务，再组织可支持比较的证据。

软目标与配额不同：5–8篇是宽主题的覆盖目标；目标不足时触发有界补检，但只有直接相关且满足约束的论文能进入回答。细分任务只有一篇时就只有一篇。不能用同器官的不同任务填满数量，也不能把搜索失败说成领域没有研究。

去重不仅看DOI。期刊与存储库可能给同一工作不同DOI。当前只对规范题名和摘要同时一致的候选判同工作，避免不可靠的模糊合并；记录保留，但只算一项独立证据。不同摘要的版本还需要后续明确版本关系。

全文预算要计真正的获取尝试。元数据阶段发现许可不允许，不应该消耗可下载论文名额。实际HTTP失败也会消耗尝试数；缓存命中不下载、不重编码。三篇/六HTTP及时间上限共同限制成本，不保证每题必有三篇全文。

向量相似不等于精确的章节相关。例如询问采集参数，患者纳入段也会重复CT/MRI词。先限定已筛选论文，再召回向量候选、补入匹配“采集/结果/局限”等通用章节意图的少量段落，最后重排。章节标签是导航，内容是否支持结论还要阅读原文。

evidence_groups用已经校验的摘要assessment把chunk ID按问题维度组合；不是增加一次LLM，更不是预先生成结论。现有模型读取这些组与原文，在同一次生成中写跨论文分析。可选section标签只组织展示，每条研究结论仍绑定真实chunk ID。不会因标题看起来合理就放松引用检查。

最小Demo的执行顺序是：读冻结元数据→解析JATS→按中文问题重排章节→打印章节及文本片段。真实系统另有在线检索、缓存与模型调用，见下一篇。
