# Clinical Literature Agent

## 项目目标

从零构建一个基于 RAG + LangGraph + PubMed + 飞书机器人的医学文献检索与循证问答系统。

参考项目：

https://github.com/ismashiping/clinicalagent

参考其业务思路和模块设计，但不直接照搬代码。优先使用成熟开源技术。

## 开发阶段

### Phase 0：工程初始化

完成技术调研、架构设计、SPEC、依赖管理、测试基础设施和最小工程骨架。

### Phase 1：MVP

实现：

- PDF 和 PubMed 文献离线入库
- Embedding 和 pgvector
- 本地 RAG 检索
- 带证据引用的医学问答
- 飞书机器人官方 SDK 长连接
- 文本消息
- 自身消息过滤
- Redis 消息去重
- 线程池异步处理
- 失败回复
- Docker Compose feishu_bot 服务

飞书相关代码划分在 src/feishu/ 下，约 5 个职责清晰的模块。

### Phase 2：异步体验

快速确认、任务状态、后台执行、超时及错误反馈。

### Phase 3：问题分类与 PICO

临床问题分类、PICO 结构化与查询规划。

### Phase 4：PubMed 实时检索

查询规划、官方 API、实时获取元数据、排序及日期过滤。

### Phase 5：混合检索

关键词、向量、融合排序与重排。

### Phase 6：证据分析

研究类型识别、证据质量、局限性和冲突分析。

### Phase 7：引用核验与报告

引用验证、论断与证据匹配、结构化医学报告。

### Phase 8：知识库更新

增量入库、定期同步、去重、版本管理。

### Phase 9：评估体系

检索召回、回答准确性、引用可靠性、性能和回归测试。

## 核心要求

1. 每个阶段先写 SPEC，再进行 TDD。
2. 每个阶段必须独立验收。
3. 每个阶段完成后生成零基础学习文档。
4. 学习文档必须结合真实代码。
5. 保证引用可追溯，不得编造医学文献。
6. 不进行超出检索证据支持范围的医学断言。
7. 不为了架构复杂度而增加不必要的组件。
8. 所有阶段逐步开发，不得一次性完成。
